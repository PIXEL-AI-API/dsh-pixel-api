# dsh-pixel-api

DeepSeek Harness 插件：用 [PIXEL](https://api.ai-pixel.online) 主站账号登录后，把账号可用的分组与模型挂载成模型来源，对话直接扣主站钱包余额，**不需要创建 API Key**。

## 安装

在 DeepSeek Harness 的 **插件 → 添加插件** 里填 GitHub 仓库地址：

```
https://github.com/PIXEL-AI-API/dsh-pixel-api
```

需要固定某个版本时在末尾加提交号或标签，例如：

```
https://github.com/PIXEL-AI-API/dsh-pixel-api#v0.1.0
```

也可以填本地目录路径，或把仓库克隆到本地后填该目录。想以后在设置页一键更新，直接填不带 `#` 的仓库地址（见下面「更新」）。

## 使用

1. 打开 **设置 → PIXEL API**，输入主站用户名和密码登录（账号启用两步验证时，会要求输入一次 TOTP 验证码）。
2. 登录成功后卡片显示账号、用户分组、钱包余额、已用金额与请求次数；点「刷新」可立即更新，「充值」打开主站钱包页。
3. 打开任意会话，点输入框右下角的模型名，在左栏选分组、右栏选模型即可对话。

对话按主站该分组当前的计费倍率扣主站钱包余额。

## 更新

- **0.2.3 及以后**：在 **设置 → PIXEL API → 插件更新** 点「检查更新」，有新版本时点「更新到 vX.Y.Z」并确认。更新由 Harness 的插件管理完成：先移除当前版本，再安装新版本，期间 PIXEL 模型和设置页会暂时消失；安装失败会自动恢复当前版本。登录状态和设置都保留。
  - 只有从 GitHub 地址安装、并被插件管理记录为固定到某个提交的副本能一键更新。从本地目录或 npm 安装的副本只显示最新版本号：本地目录请在仓库里更新代码，npm 副本在 **插件 → 已安装** 里更新。设置页提示「安装来源没有固定到具体提交」时，移除后用不带 `#` 的地址重新添加。
- **0.2.2 及更早**：这些版本没有更新入口，需要手动更新一次：**插件** 页找到 PIXEL API → 移除 → **添加插件**，重新填 GitHub 地址。移除不会删掉 `cordis.patch.yml` 里的设置，也不会删掉已保存的登录会话，重装后会自动登录（会话约 30 天内有效）。
- 新版本以 `vX.Y.Z` 标签发布，预发布标签（如 `v0.3.0-rc.1`）不会提示。

## 模型菜单变成左右两栏

登录成功后，输入框的模型菜单会替换为：

- **左栏**：模型分组，每行显示分组名、计费倍率（`×0.25`，低于 1 绿色、高于 1 橙色）、分组 ID（`ID: xxx`）；顶部搜索框可按分组名、分组 ID 或模型名搜索。
- **右栏**：该分组下的模型，当前选中的打勾；底部一行是推理等级（该模型支持时）。

键盘：`↑`/`↓` 选模型，`Alt` + `←`/`→` 切换分组，`Enter` 确认，`Esc` 关闭。

这个菜单替换的是 Harness 的通用模型菜单，因此对 **所有** 模型来源（DeepSeek、其他第三方提供方）同样生效，不只是 PIXEL。

## 安全与隐私

- **密码只用一次**：登录成功后立即从本机凭据库删除，不会以明文留在磁盘上。本机只保留主站签发的登录会话令牌（相当于浏览器里的登录状态）。
- **会话有效期约 30 天**，会自动续期；失效后需要重新输入一次密码。
- **断网不会退出登录**：断网、主站重启或返回 5xx 时，插件保留登录状态并在后台自动重试（15 秒起，每次间隔加倍，最长 5 分钟一次），期间设置页显示「暂时连不上 PIXEL 主站，登录状态已保留，稍后自动重试」，不用重新输入密码；只有主站明确拒绝续期会话时，才需要重新登录。
- **点「退出登录」会通知主站注销该会话**，不是只删本地记录。
- **所有发往主站的请求拒绝重定向**，避免带凭据的请求被转发到其他地址。
- 发往主站的数据：分组与模型列表、账号余额等账户信息；对话内容经主站转发给所选模型。插件不会上传你的本地文件或会话记录。
- 除主站外，插件只在你点「检查更新」时访问插件的 Git 仓库（GitHub），用 git 读取版本标签（即 `git ls-remote --tags`，走你的 git 代理设置；git 不可用时改用 HTTPS 读取同样的信息），不发送任何账户、会话或本地数据。平时不会自动联网检查。
- 调试日志默认关闭。在插件配置里设 `debug: true`（或设环境变量 `PIXEL_API_DEBUG=1`）后，会在 `~/.dsh/pixel-api/debug.log` 记录执行步骤与 HTTP 状态码，**不含令牌、Cookie、密码或响应内容**，文件超过 512 KB 自动换新。

## 支持的能力

- **文本与工具调用**：标准的对话、多轮工具调用、思考内容回传。工具结果按 OpenAI 的 `tool` 消息发送，紧跟在发起调用的那条回复之后；工具结果里的图片随后以一条 user 消息附上。
- **图片输入**：带图片的消息按 OpenAI `image_url` 数据 URL 发给主站，由主站转发给所选分组的上游模型。能否被理解取决于该分组背后的模型是否支持视觉；只支持文本的模型会由上游自己报错，错误信息原样显示。图片先按 Harness 的附件策略归一化（默认上限 1M 像素、约 1.5 MB），过旧的历史图片可能被替换成占位文字而不是让整次请求失败。
- **推理等级**：模型菜单底部提供 `Minimal / Low / Medium / High / Xhigh / Max` 六档，选中后以 `reasoning_effort` 字段发给主站，由主站转换成各上游模型的格式（Claude 的 `output_config.effort`、Gemini 的 `thinkingConfig`、OpenAI 直传）。**不选则不发该字段**，由上游使用自己的默认强度。各分组背后的实际模型由主站决定，因此档位对所有分组统一显示；不支持思考的模型由上游自行报错。
- **上下文窗口**：插件为每个 PIXEL 模型向 Harness 声明上下文窗口，Harness 据此决定何时自动压缩历史，以及会话中途能否切换到该模型。主站不提供各模型的实际上限，**默认按 272,000 token 计算**；在 **设置 → PIXEL API → 上下文窗口** 可以改默认值，也可以按模型单独设置（每行 `模型 ID = token 数`，以 `*` 结尾按前缀匹配，如 `gemini-* = 1048576`；精确 ID 优先，较长前缀优先，不区分大小写），从下一次请求起生效。窗口必须大于 65,536（Harness 压缩默认预留的余量），否则切换到该模型仍会被拒绝。宁可设小：设大了，历史超出上游真实上限时请求会失败。
- **用量与缓存**：按主站返回的 `prompt_tokens_details` 分别记录缓存读取、缓存写入和未命中的输入，客户端的缓存命中率由此计算；0.2.2 及更早版本把缓存一律记为 0，客户端总显示 0%。已经记录的历史轮次不会改变，从更新后的请求开始生效。
- **错误分类**：主站和上游的错误按 Harness 的错误码上报，Harness 据此决定要不要自动重试：
  - **自动重试**（Harness 默认最多 5 次，间隔逐次加长）：`SERVER`（主站或上游 5xx：服务不可用、过载、超时、网关错误）、`RATE_LIMIT`（429 限流；主站带了 `Retry-After` 就按它等待，要求等待超过 10 秒时不自动重试，稍后手动重发即可）、`EMPTY_RESPONSE`（上游回了空回复），以及连不上主站（`TRANSPORT`）、流长时间没有数据（`TIMEOUT`）。
  - **不重试，需要你处理**：
    - `QUOTA`：钱包余额不足时去充值；分组单人每日或总额度、次数用完时（`room_member_limit_exceeded`，虽是 429，等一会儿也不会恢复），等额度重置或联系分组。
    - `PRICE_CONFIRMATION_REQUIRED`：分组倍率或模型价格上调待确认，到主站确认新价格后重发。
    - `SESSION_BLOCKED`：上游封锁了当前会话，新开会话再发；在原会话里重试会一直失败。
    - `ACCESS_DENIED`：分组拒绝该账号（被拉黑、暂未开放等），按主站给的原因处理，或联系分组。这类 403 不报 `AUTH`：Harness 聊天界面遇到 `AUTH` 只显示通用提示，看不到主站给的原因。
    - `AUTH`：只在登录确实失效时出现（主站拒绝续期会话，或续期后主站仍回 401），到设置页重新登录。续期时连不上主站或主站出错不算失效，按 `TRANSPORT`、`SERVER`、`RATE_LIMIT` 报告并自动重试。
    - `CONTEXT_WINDOW_EXCEEDED`：超出上下文，主站把上游原文透传出来时也能识别，Harness 会尝试压缩后重试一次。
    - `CONTENT_REFUSED`：上游按内容安全策略拒绝（`finish_reason: content_filter` 或主站的内容策略错误），与 Harness 0.2.2-rc.4 起 DeepSeek 拒答的错误码一致。
    - `INVALID_REQUEST`：其余请求错误（400、413 等），主站原文照常显示。
  - **流中报错同样识别**：回复已经开始输出、主站才在流里报错时（`error` 帧，后面带不带 `[DONE]` 都一样），按上面同样分类，不会被当成连接中断（`STREAM_CLOSED`）、空回复或正常结束；已输出的内容和用量照常记录。
  - 每个失败都带主站的请求编号（响应头 `X-Oneapi-Request-Id`，记在错误的 `requestId` 里），反馈问题时提供它，便于在主站日志里定位。

## 限制

- 分组倍率与模型列表在登录时拉取；主站改了倍率后，点一次「刷新」或重新登录即可同步。
- **版本兼容**：支持 Harness `0.2.2-rc.1` 及以上、`0.3.0` 以下（见 `package.json` 的 `engines.dsh`）。0.2.3 起在 0.2.2-rc.3 桌面版运行时与 0.2.2-rc.5 的运行时包上通过 `test/` 下的检查。
  - 图片输入依赖 Harness 的 `@deepseek-ai/dsh-attachment` 包。若该运行时没有这个包，插件照常加载、文本对话正常，只是在发送带图片的消息时会明确提示图片不可用，而不是整个插件加载失败。
  - 图片缩放优先调用运行时的 `requestImageDimensions`；运行时未提供时使用插件内置的等价实现（已逐项对照官方算法验证一致）。

## 开发检查

不联网、不用真实账号，主站接口全部在本地模拟：

- `test/check-context.mjs`：用真实的 Harness `LlmRuntime` 加载插件，检查上下文窗口声明、按模型覆盖、设置页即时修改、错误分类（HTTP 错误与流中报错帧对应的错误码、`Retry-After`、请求编号）、会话续期失败的处理（连不上主站或 5xx 时保留登录并定时重试，主站明确拒绝时才退出登录）、工具结果的发送格式（`tool` 消息、图片随后附上、空的 system 消息不发送），以及各类上游的缓存用量映射。桌面版运行时下用 `ELECTRON_RUN_AS_NODE=1 "<DeepSeek Harness.exe>" test/check-context.mjs` 运行；能直接解析 `@deepseek-ai/*` 包的环境用 `node test/check-context.mjs`。
- `test/check-update.mjs`：一键更新。用真实的 git 读本地临时仓库里的真实标签，用插件管理自带的来源校验判断更新目标，再用假的插件管理逐一模拟更新结果（更新中被移除、拒绝、需要重启、失败后恢复），不安装任何东西。运行方式同上，需要 PATH 里有 git。
- `test/check-client.mjs`：在 vm 里执行 `client.js`，操作设置页的上下文窗口卡片（显示、校验、保存、恢复默认）和插件更新卡片（检查、确认、各状态显示）。`node test/check-client.mjs`。
- `test/check-load.mjs`、`test/check-fallback.mjs`：配置解析与图片缩放。

## 停用

在 **插件** 页关闭本插件后，PIXEL 的模型来源立即从模型选择器移除。已有会话记录不受影响；要彻底清除登录状态，请先在设置页点「退出登录」。
